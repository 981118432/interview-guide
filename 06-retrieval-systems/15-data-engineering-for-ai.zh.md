# 面向 AI 的数据工程

模型的好坏取决于输入数据，而任何严肃 AI 系统的大部分工作都发生在模型上游。本章介绍同时服务于 RAG 和微调的**数据层**：摄取、清洗、去重、PII 与治理、质量过滤，以及负责移动这些数据的流水线。它被放在检索章节，是因为多数团队最先在 RAG 中遇到这些问题，但它是**横切能力**：准备向量库文档的流水线，也在准备微调样本。把数据工程视为“RAG 的第二步”低估了它；它是两个消费者都依赖的独立学科。

## 共享流水线

核心思想是：一条流水线，两个消费者。RAG 需要对文档进行解析、清洗、去重、分块、增强和 Embedding。微调需要对样本进行解析、清洗、去重、质量过滤、相对于评测集去污染、平衡和格式化。前五个阶段是**共享的**，只有末端才分叉。

```
SOURCES        web · docs (PDF/office/email) · DBs/APIs · uploads
   |
[1] DETECT & ROUTE    MIME sniff -> language ID -> route by type
[2] PARSE / EXTRACT   typed elements + structure
[3] CLEAN / NORMALIZE boilerplate strip · encoding repair · unicode · language filter
[4] DEDUP             exact -> MinHash/LSH -> semantic (SemDeDup)
[5] GOVERN            PII detect/redact · license/consent/provenance metadata
[6] QUALITY FILTER    heuristics + model classifier  [always ablate on a downstream eval]
   |-- RAG branch ---------------------|   |-- FINE-TUNE branch ----------------|
   | [7a] chunk -> enrich -> embed     |   | [7b] curate/label -> synthesize    |
   |      -> VECTOR STORE (CDC-fresh)  |   |      -> decontaminate -> balance   |
   |-----------------------------------|   |      -> TRAINING RECORDS           |
CROSS-CUTTING   orchestration (Airflow/Dagster) · lineage (OpenLineage) · versioning (DVC/lakeFS)
```

“大部分工作”这一说法经得起时间考验：从业者约 80% 时间用于数据准备这一广为流传的经验，更接近在许多来源中反复出现的民间说法，而不是经过测量的结论；但方向是对的。供应商声称 AI Agent 现在可以把准备时间缩短 50～70%，则未经验证且带有利益倾向。两者都只能作为方向性参考。

## 数据摄取

输入是一堆异构数据（PDF、扫描件、Office 文档、HTML、邮件、图像）。必须识别每个文件是什么，把它路由到合适的解析器，并输出规范化的结构化表示。

- **根据内容而不是扩展名检测文件类型。**标准做法是使用 `libmagic` 通过魔数嗅探（它是 Unix `file` 命令背后的库），再通过 `python-magic` 等绑定暴露出来。Unstructured 等解析器也会这样自动识别类型，并在必要时回退到扩展名。
- **语言检测**用于路由和过滤，常用 fastText 的语言分类器。
- **解析和路由。**内容类型决定处理器：可提取文本的 PDF 走快速文本路径，扫描 PDF 或图像 PDF 走 OCR，复杂的多栏或表格密集文档走布局模型或多模态（按页截图）路径，Office 文档使用格式专用处理器，邮件拆分为头部和正文。领先工具包包括 **Unstructured**（支持 64+ 种文件类型，输出 Title/NarrativeText/Table 等带类型元素）、**Docling**（IBM，MIT 许可证，提供布局和表格模型以及多种导出格式）和 **LlamaParse**（分级 API 模式，最高支持多模态 Agent 化解析）。需要强调：已发布的解析器基准相互矛盾，因此应该**在自己的文档上测试解析器选择**，而不是盲信排行榜。

## 清洗与规范化

共享的第一道质量门：
- **去除样板内容。**清除导航、广告、页眉、页脚、Cookie 横幅。对于大规模 HTML，标准做法是使用内容抽取库；FineWeb 项目发现，使用这类工具从原始 Web 归档中抽取内容，比使用预先抽取的文本更好，因为后者“保留了太多样板内容”。因此这是上游质量问题，而不是表面美化。
- **修复编码**，包括乱码和二次编码文本，同时规范化换行符。
- **Unicode 规范化**（NFC/NFKC），让视觉上相同的字符串比较结果相同，这是去重和匹配正常工作的前提。
- **语言过滤**，去掉低于置信度阈值的内容。

一个值得讲授的反直觉注意点是：**过滤越多不一定越好。**FineWeb 的消融实验发现，许多启发式规则影响很小或只有边际收益（收益太少，因此移除了大多数候选过滤器）；Nemotron-CC（arXiv:2412.02595）报告称，激进的启发式过滤可能丢弃约 18% 的、其自身质量分类器判为高质量的 Token。过滤器必须对下游评测做消融，而不能想当然。

## 去重

去重是杠杆最大的一步，也是最能体现“共享基础设施”价值的一步，因为一次操作可以带来三方面收益。基础研究结果（Lee 等，arXiv:2107.06499）表明，对训练数据去重会让模型生成记忆文本的频率降低约 10 倍，在更少训练步数内达到相同或更高准确率，而且关键是，**去重会减少训练集与测试集重叠，因此去重也是去污染**。它还通过减少重复 PII 的记忆来降低隐私风险。

三个层级应组成级联（先便宜且精确，后昂贵且语义化）：
1. **精确去重**：对整个文档或规范化后的子串做 Hash。快速且精确，只能捕获逐字副本。
2. **模糊/近重复去重**：**MinHash + LSH** 基于 Token n-gram Shingle 估算 Jaccard 相似度，并把候选分桶，避免全量两两比较（Web 规模的默认方式；现在一些向量数据库已经将其作为原生索引提供）。SimHash 是经典替代方案。注意：这些方法是*词法*的，因此可能错误地删除共享模板但含义不同的文档。
3. **语义/Embedding 去重**：**SemDeDup**（arXiv:2303.09540）为每个项目做 Embedding，聚类后根据余弦相似度删除簇内近重复项；据报道，在性能损失很小的情况下，它从大型图文数据集移除了约 50% 的内容，也能捕获 MinHash 漏掉的释义改写。

生产模式是组合这些层级：先 MinHash，再 SemDeDup。要明确说出三方面收益：RAG（重复块浪费上下文窗口、挤占多样证据），训练（减少记忆、减少训练步数），以及评测完整性（针对基准去重可以防止污染）。

## PII、同意与治理

**PII 检测和脱敏。**Microsoft Presidio（MIT）是开放标准：Analyzer 通过 NER 加正则、校验和与上下文词检测实体，Anonymizer 则进行脱敏、替换、掩码、Hash 或加密，覆盖文本、图像（带 OCR）和结构化数据，并可在语料库规模部署。由于去重会减少重复驱动的记忆，隐私与去重是相互关联的。

**同意、许可和溯源**如今是监管要求，而不仅仅是卫生习惯。根据欧盟 AI 法案，通用模型供应商必须保留版权政策，并使用 AI Office 的强制模板发布训练内容的“足够详细摘要”，包括数据来源以及对版权退出声明的遵守（这项摘要义务自 2025 年 8 月起适用于新的通用模型，已经上市的模型则有过渡期至 2027 年 8 月）。随后还会有输出标记义务。对流水线的治理含义是：从摄取开始，每条记录都携带来源、许可、同意状态和时间戳元数据，而这正是下面的 Lineage 提供的能力。治理不是最后一道门，而是贯穿每个阶段的元数据。参见[AI 治理与合规](../13-reliability-and-safety/04-ai-governance-and-compliance.md)。

## 质量过滤与增强

**质量过滤**分为两类。**启发式**规则（长度、符号/词比例、重复度、停用词存在性）便宜，但无法捕捉复杂内容噪声。**基于模型的分类器**为质量或教育价值评分；FineWeb-Edu 用 LLM 生成的质量标注训练轻量分类器，并报告了显著的下游收益：用少得多的 Token 匹配更大语料库的效果。需要特别指出：分类器过滤不是免费午餐（“数据质量错觉”相关研究认为它可能校准不当），因此**始终要在下游评测上对过滤器做消融，不要因为名气而信任它们**。

**分块**（RAG 侧阶段）没有通用赢家：已发布基准在固定大小、递归和语义策略之间波动很大，因此它取决于数据集，必须评估，不能直接采用默认值。参见[分块策略](02-chunking-strategies.md)。

**增强和元数据。**附加标准元数据（标题、作者、时间戳、来源、章节）以及生成元数据（块摘要、上下文前缀、块能够回答的合成问题），这会把单轴向量相似度变成多维过滤搜索。参见[上下文检索](10-contextual-retrieval.md)。

**Lineage。**OpenLineage（Marquez 是参考实现）是跟踪运行、作业和数据集事件的厂商中立标准；对 ML 来说，它还把图谱向前扩展到特征表、模型和预测。结合数据版本管理（DVC、lakeFS、Delta/Iceberg 的时间旅行），这就是让治理元数据端到端可审计的基础设施。

## 流水线与编排

**批处理与流处理。**预训练语料准备和批量 RAG 索引是批处理作业（在对象存储上运行 Spark 或 Ray）。RAG 的*新鲜度*是增量的：源文档变化时，只重新摄取差异。变更数据捕获实时记录源数据的行级变化；映射到 RAG，就是“检测变化、新增和删除的文档，只重新解析和重新 Embedding 这些文档，然后在向量库中 Upsert 或删除”，避免完整重建索引，并防止过时或孤立向量。

**编排器。**Airflow 生态最大，是默认选择；Dagster 以资产为中心，支持增量重算，适合增量 RAG 重 Embedding；Prefect 是更轻量、更 Pythonic 的选项。Spark 和 Ray 是编排器调度的分布式计算工具，不是编排器本身。

**向量库与特征库。**流水线在末端分叉：RAG 将块 Embedding 加元数据写入**向量存储**（检索服务层），微调将精选样本写入具备时间点正确性的**特征或训练记录存储**。两者都依赖同一条共享主干。

## 用于微调的数据

与 RAG 分叉的末端：
- **精选胜过数量。**一小组精心整理的样本经常胜过大量平庸样本；质量三要素是难度、质量和多样性。（“1,000 胜过 10,000”这样的精确数字只是示例，不是规律。）
- **合成数据**（从小型种子集出发，通过教师模型进行 Self-Instruct 风格扩展，再过滤）扩展成本低，但如果生成方式不谨慎，会导致多样性坍缩和模型退化，因此多样性必须是一等目标。参见[合成数据生成](../03-training-and-adaptation/06-synthetic-data-generation.md)。
- **去污染是必做项。**相关研究结果（arXiv:2311.04850）指出，*改写或翻译后的*测试样本会绕过 n-gram 去污染，使用这些数据训练的模型可能在基准上过拟合到接近前沿的分数。甚至由前沿模型生成的合成数据也被发现存在污染。规则是：使用基于 Embedding 或 LLM 的匹配，而不只是 n-gram 重叠进行去污染；并且在每次评测前都做，因为污染会悄悄抬高分数。参见[基准与排行榜](../14-evaluation-and-observability/03-benchmarks-and-leaderboards.md)。

## 失败模式

1. **相信文件扩展名**，而不是魔数检测（解析器错误，静默地产生垃圾）。
2. **用纯文本路径解析扫描 PDF**（提取为空或不完整；应把图像 PDF 路由到 OCR 或多模态路径）。
3. **从已经去除样板内容的 HTML 中提取**（样板污染；应从原始内容配合内容抽取工具提取）。
4. **跳过 Unicode 规范化**（精确去重和匹配会静默漏掉重复项）。
5. **在错误层级去重**（单独使用 MinHash 会漏掉释义改写；应级联精确、模糊、语义去重）。
6. **启发式过滤过于激进**（Nemotron-CC 报告它可能丢弃约 18% 的高质量 Token；每个过滤器都要做消融）。
7. **因为质量分类器有名就信任它**（数据质量错觉；要做下游验证）。
8. **训练前不做 PII 脱敏**（PII 被记忆并回吐，重复越多越严重）。
9. **没有许可、同意或溯源元数据**（无法审计的语料库，也无法满足训练内容摘要义务）。
10. **评测污染这个沉默的杀手**（仅基于 n-gram 的去污染会漏掉改写测试项；使用 Embedding 或 LLM 去污染）。
11. **RAG 索引过时**（不使用 CDC 而完整重建索引；成本暴涨、答案过时、出现孤立向量）。
12. **默认采用糟糕的分块**（基准结论不一致；应按数据集评估）。
13. **没有 Lineage**（数据集不可复现、回归问题无法调试；从第一天起就输出 Lineage）。

## 面试问题

### Q：为什么去重是 AI 数据流水线中最重要的阶段之一？

**强回答：**

因为一次操作能带来三种不同收益。对于训练，去重会减少记忆（模型回吐训练文本的次数大幅下降），并在更少训练步数内达到相同或更高准确率，因此节省计算。对于 RAG，重复块会浪费上下文窗口、挤占多样证据，伤害检索质量。更关键的是，对基准去重本身也是去污染：基础研究发现，删除重复项也会删除抬高评测分数的训练-测试重叠。在实践中，我会采用级联：先做精确 Hash，再用带 LSH 的 MinHash 处理近重复，最后用语义 Embedding 去重捕获词法方法漏掉的释义改写，因为每个层级都能捕获更便宜层级无法捕获的内容。

### Q：如何让评测结果不受数据污染影响？

**强回答：**

陷阱在于，简单的 n-gram 去污染并不够。一个广为人知的结果表明，测试样本的改写或翻译版本会直接绕过 n-gram 匹配；用它们训练的模型可能在基准上过拟合到接近前沿的分数，甚至强模型生成的合成数据也会受到污染。因此我会使用语义方法去污染——Embedding 相似度搜索加 LLM 裁决器，而不只是字符串重叠——并且在每次评测前对所有评测集执行。更广泛地说，在可能时我偏好留出的或新发布的测试集，把任何基准都视为可能被污染，并依赖自己的黄金数据做关键决策，因为这是唯一能保证模型没有见过的数据集。
