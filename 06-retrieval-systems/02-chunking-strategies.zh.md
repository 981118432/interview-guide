# 分块策略

分块是把文档拆成可用于检索的离散片段的过程。生产流水线已经从盲目的固定大小切分，发展到**结构感知和语义分段**，晚分块和上下文前置等新技术也已经进入主流工具箱。

## 检索与上下文的张力

| 方面 | 小分块（100t） | 大分块（1000t） |
|------|----------------|-----------------|
| **精度** | 高（精确匹配） | 低（被稀释） |
| **上下文** | 差（句子被打断） | 丰富（包含周边信息） |
| **存储** | 高（向量更多） | 低（向量更少） |
| **延迟** | 低（搜索快） | 高（检索重） |

**原则**：小分块更适合*查找*，大分块更适合*思考*。使用**层级分块**可以兼得两者。

## 递归结构切分

不要每 500 个字符盲目切分，而是按照逻辑边界切分：`[双换行] > [单换行] > [句号] > [空格]`。

**最佳实践**：使用**Markdown 感知切分**。如果文档包含 `#` 标题，应确保标题被前置到*每个*子块中，以保留上下文（上下文分块）。

## 语义分块

语义分块使用 Embedding 模型检测“主题变化”。

1. 把文本拆成单独的句子。
2. 只要句子之间的 Embedding 相似度高于阈值（例如 0.82），就继续分组。
3. 如果相似度下降，则开始新的分块。

**细节**：生产流水线越来越多地使用**Cross-Encoder 分段器**。小模型扫描文本，在每个语义断点预测一个“分隔 Token”。它比基于余弦相似度阈值的方法准确 10 倍。

## 层级（父子）分块

这是生产 RAG 的行业标准。

- **流程**：
  1. 创建 1,500 Token 的“父”块。
  2. 将每个父块进一步拆成 5 个 300 Token 的“子”块。
  3. **只索引子块**。
  4. 检索时，如果某个子块匹配，则把完整的父上下文返回给 LLM。
- **为什么？**：子块小，向量数据库容易匹配；父块提供足够的上下文，让 LLM 能真正正确推理，而不会因为“上下文断裂”产生幻觉。

## 内容特定策略

### 1. 代码分块

- **策略**：使用 AST（抽象语法树）解析。
- **规则**：绝不要从函数体中间切分。让导入和类声明与其方法保持在一起。

### 2. 表格分块

- **策略**：使用 Markdown 格式表达表格。
- **现代模式**：“摘要表格”。把表格的自然语言摘要存入向量数据库，但把完整 Markdown 表格返回给 LLM。

### 3. PDF/布局分块

- **策略**：使用**视觉语言模型（VLM）**预处理（例如 ColPali）。
- **细节**：不要只存储文本，而是存储表达页面*位置布局*的 Embedding，确保图表和侧边栏不会混入正文。

## 面试问题

### Q：为什么带重叠的固定大小分块不适合生产系统？

**强回答：**

固定大小分块是“内容盲”的。它经常在思路中间切断句子、拆开数学公式，或把标题与描述性文本分开。虽然“重叠”（例如 10%）通过在多个块中重复 10% 的文本有所缓解，但没有解决根本问题：模型必须从碎片化字符串中重新构建意义。现代流水线更偏好**语义或逻辑分块**，因为它确保每个向量都代表一个“完整语义单元”，从而显著提高检索精度。

### Q：什么是“上下文检索”（Anthropic 模式）？

**强回答：**

上下文检索是在每个块被 Embedding 前，给它前置一句全局上下文。例如，一个块提到“续航时间”，但如果没有标题，我们不知道“它”指的是“2025 Model X 无人机”。上下文检索会把 `[Drone_Model_X_Manual]:` 加到块前面，让“电池续航”这个向量受到“无人机”上下文影响，避免它被错误地用于“手机电池”查询。
