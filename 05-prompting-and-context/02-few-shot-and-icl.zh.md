# Few-Shot 与上下文学习（ICL）

上下文学习（ICL）是 LLM 仅通过在 Prompt 中看到示例、无需更新权重就学会新任务的能力。最大化 ICL 效率是提升 Prompt 稳定性的关键杠杆。

## Few-Shot 示例的构成

高质量示例由三部分组成：
1. **输入**：一份真实的潜在用户数据样本。
2. **推理（可选）**：简短解释结果*为什么*是这样。
3. **输出**：“黄金标准”结果。

```markdown
User: "The weather is okay, but the flight was late."
Reasoning: The user is neutral about the weather but negative about the service.
Sentiment: Mixed
```

## 需要多少示例？

| 模型规模 | 最佳区间 | 扩展行为 |
|----------|----------|----------|
| **小型（8B）** | 5～10 | 收益会持续到约 20 个示例。 |
| **中型（70B）** | 3～5 | 很早就进入平台期；更多示例只会增加延迟。 |
| **前沿（405B）** | 1～2 | 能力很强；通常只遵循指令就足够。 |

**经验法则**：如果需要超过 20 个示例才能获得稳定输出，那么任务可能对该模型来说过于复杂，或者应该考虑**微调**。

## 动态示例选择

在生产 RAG 或分类中，不要对每个用户都使用相同的静态示例。
**动态模式：**
1. 用户提供查询。
2. 在“黄金示例向量数据库”中搜索语义最相似的 3 个案例。
3. 将这 3 个具体案例注入 Prompt。

**结果**：模型看到与当前用户相关的“局部”模式，准确率会大幅提高。

## 标签细节的重要性

前沿模型对示例中的**分布偏差**很敏感。
- 如果提供 5 个“正面”示例和 1 个“负面”示例，模型会偏向“正面”。
- **修复**：始终使用**标签平衡**。确保 Few-Shot 示例大致反映预期输出分布，或者完全平衡（1:1）。

## 高级 ICL：类比与“Few-Shot CoT”

**类比 Prompt**：不要只说“做 X”，而是提供一个类比。
“像译者把一首诗从法语移到英语那样翻译这段代码——保留灵魂（逻辑），但改变语法。”

**Few-Shot CoT**：提供 2 个推理过程明确的示例。这会“预热”模型的注意力，让它聚焦逻辑，而不是只模仿输出字符串。

## 面试问题

### Q：为什么不把已有的 50 个示例全部放进 Prompt？

**强回答：**

主要有三个原因：
1. **上下文窗口延迟**：每个示例都会增加 Token，进而增加 Prefill 时间和每次请求的成本。
2. **注意力稀释**：即使有 128k 上下文，如果特定约束埋在过多无关数据中，模型也可能“丢失”它们（即“中间丢失”效应）。
3. **过拟合**：太多狭窄示例会导致模型过度模仿示例的*格式*，失去处理集合之外边界案例的通用能力。

### Q：上下文学习中的“标签偏差”是什么？

**强回答：**

标签偏差是指，模型仅仅因为某个标签在 Few-Shot 示例中出现得更多，或因为它出现在列表末尾，就更频繁地预测该标签。标准缓解方式是：
1. 对不同请求打乱示例顺序。
2. 确保正面/负面/中性样本数量相等。
3. 在 Prompt 开发期间使用“置换测试”，确认模型响应的是内容，而不是顺序。
