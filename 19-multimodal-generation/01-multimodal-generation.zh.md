# 多模态生成

生成图像、视频和音频，与理解它们是不同的工程问题。生成媒体产品是一个由**长期运行、非确定性、昂贵任务组成的资产处理流水线**；大部分工作在于安全编排、证明来源，以及评估无法精确复现的质量。本章先讲这些持久问题，把具体模型当作会过期的快照。除非绑定到一手来源，以下所有能力数字都是报告值或供应商声明。

**范围（先读）：** 对创意、媒体、营销、游戏和虚拟形象产品，本主题是核心内容；对后端服务、数据平台、RAG 和纯文本 Agent 则大多是噪声。任何处理用户上传或 AI 生成媒体的产品都必须关注的部分是**来源证明与安全**，因为法律义务约束的是生成或分发合成媒体，而不是你的业务领域。如果系统从不输出像素或波形，只有这一节适用。

## 生产流水线模式

这部分比任何具体模型都更持久。

**链式处理是一张 DAG，不是一次调用。** 典型创意流水线是一张阶段图，通常每个阶段使用不同供应商的不同模型：`prompt -> image (keyframes/style) -> image-to-video -> lip-sync -> voice/TTS -> music/SFX -> mux`。持久的经验是**在阶段边界分离关注点**，让任一阶段都可替换；这与[语音 Agent](../18-voice-and-audio-agents/01-realtime-voice-agents.md)章节讨论的级联与单体权衡相同。节点图工具（ComfyUI）把这一方式用于图像和视频；应把工作流图当成有版本的代码，而不是 UI 状态。

**异步、队列和长任务处理是强制要求。** 图像生成需要几秒，**视频生成每个片段需要几十秒到几分钟**，因此同步请求无法生存。通用模式是：提交接口立即返回 Job ID，GPU Worker 池后台执行，客户端通过 Webhook 回调获知完成（并提供轮询兜底，因为 Webhook 会丢失）。验证 Webhook 签名，并根据**队列深度**而不是 CPU 自动扩容。单个视频任务要花真实的钱和几分钟时间，因此每个逻辑请求都要附带幂等键，避免客户端重试或重复投递的 Webhook 付两次钱。

**成本和延迟控制**按大致杠杆排序：对完整请求指纹（Prompt + 所有参数 + Seed + 模型版本）缓存，让相同请求不会重复计费；低成本出草稿（低分辨率、少步数、小型快速模型），只把获批草稿以完整质量重渲染，这是视频中最大的节省手段；在支持时批处理；有意选择层级（Turbo 和蒸馏变体用质量换取大幅延迟与成本收益）；保持 Worker 池温热，因为加载多 GB 的检查点可能需要几十秒。

**资产与 Prompt 管理。** 把 Prompt、负面 Prompt、Seed、模型和版本，以及所有条件输入（控制图、参考图、适配器 ID 和权重）作为结构化、有版本的记录，与每个输出一起保存。没有完整参数集就无法复现或调试生成过程，而供应商会在稳定名称背后静默更换模型。这个清单也同时充当来源日志。

**Seed 与可复现性：残酷事实。** Seed 可以让*本地、已锁定*的运行可复现，但一旦跨越硬件或批次边界，可复现性就会下降；在托管 API 上则基本不存在。根因并非生成模型专属：浮点运算不满足结合律，不同 GPU Kernel 会以不同顺序累加；批次大小会改变 Kernel 策略（数值噪声最常见来源）；某些 GPU 操作除非显式强制，否则具有非确定性。实践态度是：自托管时锁定硬件、固定批次、固定库版本并使用 Seed，可以让图像接近可复现；任何托管 API，尤其视频，都应视为不可复现，因此 QA 应围绕感知相似度而不是精确匹配来设计。

## 来源证明与安全

技术会变化；标记来源的义务以及无法完美执行它的事实是持久问题。这里有两个互补层，**而且两层都可以被移除。**

**C2PA / Content Credentials** 是把来源以密码学方式绑定到资产的开放标准（媒体的“营养标签”）。清单保存创作和编辑断言、签名声明以及源资产引用，并同时提供**硬绑定**（对字节做密码学哈希，防篡改）和**软绑定**（可以经受重新编码的指纹或水印）。“持久内容凭证”会通过外部仓库中仍存活的水印或内容指纹找回被移除的清单，因为重新编码和截图会让清单与资产分离。采用正在增长：主要图像和视频生成器现在会附加 C2PA 元数据和水印，一些相机厂商会在拍摄时为照片签名，平台也会读取凭证以应用 AI 标签。值得教学的警示案例是：某相机厂商因签名密钥漏洞添加后又暂停了 C2PA，因为信任模型的安全程度不会超过密钥保管。

**水印（SynthID 风格）**给生成媒体加入不可感知信号。工程师必须牢记的持久警告是：**不可见水印无法抵御有动机的攻击者。** 同行评审研究表明，重生成攻击（加噪，再用扩散模型去噪）可以在低于某个扰动阈值的情况下证明移除不可见图像水印，同时保持质量；文本水印会被改写和回译削弱。水印可以阻止随意滥用并帮助平台标记，但不能阻止攻击者。应叠加 C2PA 签名来源、经受元数据剥离的水印和基于分类器的检测，并假设单独的任何一层都可能被击破。

**安全过滤器**在返回资产前同时进行输入审核（阻断不允许的 Prompt）和输出审核（NSFW 与身份分类器）。高严重性类别包括非自愿私密影像、真实人物 Deepfake、未经同意的声音克隆，以及版权或肖像侵权；缓解措施包括 Prompt 和区域黑名单、已知人脸拒绝、经同意的肖像使用、速率限制，以及与来源清单关联的滥用日志。

**2026 年监管背景**（这部分也适用于仅仅托管媒体的非媒体产品）：EU AI Act 透明度条款要求提供方以机器可读方式标记生成输出，部署方披露 Deepfake，相关义务自 2026 年 8 月起适用（见[AI 治理与合规](../13-reliability-and-safety/04-ai-governance-and-compliance.md)）；美国 TAKE IT DOWN Act（2025）针对包括 AI Deepfake 在内的非自愿私密影像，规定平台下架义务；州级肖像法（Tennessee ELVIS Act 以及许多露骨 Deepfake 法）保护声音和肖像。音乐和声音生成还面临未解决的版权诉讼，因此模型许可和赔偿状态是真实的采购问题。

## 评估生成质量

两个无法回避的事实：自动指标很弱，而人类偏好才是真正的 Ground Truth，但成本很高。

**自动指标及其不可靠原因。** 长期使用的图像指标 FID 与人工评分矛盾，无法正确处理失真，并且在现实样本量下存在偏差且不稳定；CLIPScore 衡量文本-图像对齐，但容易被利用，组合多个弱指标也不会产生强指标。FVD 继承 FID 的问题，在视频常见的小样本量下不稳定。音频的 FAD 是 FID 的对应物，也有相同问题；随着 TTS 接近人类质量，MOS（主观 1～5 分）现在受上限限制。这些指标只能用作粗粒度信号，绝不能当作正确性证明。

**人类偏好是黄金标准。** 业界通过盲测成对竞技场、让大量投票使用 Elo 或 TrueSkill，为图像和视频模型排名。把公开竞技场排名当成粗信号，并按自己的 Prompt 分布验证，这与[基准测试](../14-evaluation-and-observability/03-benchmarks-and-leaderboards.md)章节对 LLM 的要求相同。

**不可复现流水线的回归测试**是持久实践，因为供应商会在稳定名称后静默更新模型。构建覆盖真实用例和故障模式的有版本黄金 Prompt 集；对于托管 API 放弃精确匹配，比较指标分数的*分布*；使用感知相似度（感知哈希、SSIM、与基线的 CLIP Embedding 距离）而不是相等比较；对哈希看不到的内容，按标准加入 VLM-as-Judge（Prompt 遵循度、伪影、品牌安全）；随时间追踪 Judge 与指标分布并在漂移时告警，这通常意味着上游供应商改变了模型；API 允许时锁定带日期的模型版本。根据统计显著性而不是原始差值设发布门禁，并独立于模型管理 Prompt 版本。

## 模型版图

保持轻量并注明日期，因为版图每月变化，流传中的许多规格表细节来自低质量来源。

- **图像。** 开放权重前沿由 FLUX 家族领跑（近期版本是可在单张高端消费级 GPU 上通过量化运行的大型 Rectified-Flow Transformer，而且不需要为人物或风格参考进行微调）；Stable Diffusion 系列仍是广泛工具基础。需要强调的许可陷阱是：开放*权重*不等于开放*使用*，因为若干变体（`dev` 线）不可商用，商业工作需要付费许可，而蒸馏的 `schnell` 变体采用宽松的 Apache-2.0 协议。条件控制可以组合：ControlNet（从姿态、深度、边缘或分割图进行结构控制）、参考适配器（把图像作为风格或肖像 Prompt）、局部重绘和扩图，以及区域 Prompt；生产组合是在一张图中使用身份适配器 + 结构控制 + 文本主题。LoRA 是风格或主体个性化的默认选择。
- **视频。** 专有 API 领先者（OpenAI 的 Sora 2、Google 带原生同步音频的 Veo，以及 ByteDance、快手、Runway 等强劲竞争者）位于快速改进的开放权重层之上。需要强调一个修正，也是本节会快速过期的实时例子：OpenAI 在 2026 年 3 月弃用了 Sora 2 / Videos API（据报道将在 2026 年稍晚关闭），并很快停止消费者 Sora 应用，因此在构建视频能力前应核验模型状态，不要盲信任何快照，包括本章。计费按输出秒数（大致每秒几美分到不足 1 美元），生成需要几十秒到几分钟，输出不可复现，因此必须使用异步任务、先草稿后渲染和严格的单用户成本上限。
- **音频。** 语音和 TTS（ElevenLabs 是参考产品，支持克隆和配音）以及音乐（Suno 和 Udio，正处于持续的版权诉讼和许可和解中心）。视频合成与语音章节的拆分相似：原生联合音视频提供最好的同步和最少的控制；级联方式（生成无声视频，再分别加入 TTS、音乐和唇形同步）提供独立控制和配音能力，但更费力，所以大多数生产配音流水线仍然采用级联。

## 面试问题

### Q：设计一个把脚本转换为带旁白、带音乐视频的服务骨架。困难在哪里？

**强回答：**
骨架是由可替换模型组成的异步 DAG：Prompt 到关键帧图像、图像转视频、TTS 旁白、音乐模型配乐、唇形同步绑定声音和视频，最后执行 mux。因为视频生成需要几十秒到几分钟，每个阶段都应是一个 Job：提交返回 ID，工作在按队列深度自动扩容的 GPU Worker 池中执行，完成后通过 Webhook 通知，并提供轮询兜底。困难在成本和可靠性。成本方面，对完整请求指纹缓存，便宜地生成草稿，只把获批草稿以完整质量重渲染，并限制每个用户的花费，因为每次重试都要花真实的钱。可靠性方面，使用幂等键，避免重试或重复投递的 Job 重复付费；为每个资产保存 Prompt、Seed、参数和模型版本的完整清单，用于调试和来源记录。我还会在生成前后做审核并附加 C2PA 凭证，因为无论业务领域是什么，合成媒体义务都适用。

### Q：输出不可复现时，如何对生成流水线做回归测试？

**强回答：**
放弃精确匹配，改做感知和统计测试。维护覆盖真实用例及已知故障模式的有版本黄金 Prompt 集，在每次变更时运行。自托管、锁定硬件并使用 Seed 时，可进行 Seed 锁定检查；托管 API 则假设不可复现，比较指标分布而不是单个输出，并使用感知相似度、感知哈希、SSIM、与基线的 CLIP Embedding 距离，以及按标准评估 Prompt 遵循度和伪影的 VLM-as-Judge。随时间追踪这些分布并对漂移告警，因为突然变化通常意味着供应商静默更新了稳定名称背后的模型；API 允许时还要锁定带日期的模型版本。发布应以统计显著性为门禁，而不是原始差值，并独立管理 Prompt 与模型版本，以便将回归归因到正确的变更。
