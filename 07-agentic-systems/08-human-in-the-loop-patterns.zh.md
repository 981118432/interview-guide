# 人在回路模式

没有 Agent 是 100% 可靠的。**人在回路（HITL）**是在高风险环境中确保安全和准确性的桥梁。生产技术栈已经从“审批按钮”发展到**协同推理**和**基于中断的引导**，LangGraph（interrupt+resume）和 Microsoft Agent Framework 等框架都原生支持它们。

## HITL 谱系

| 模式 | Agent 自主性 | 人的角色 | 最适合 |
|------|--------------|----------|--------|
| **人主导** | 低 | 驱动每一步 | 高风险法律/医疗 |
| **人过滤** | 中 | 审批/编辑最终输出 | 内容生成 |
| **人兜底** | 高 | 只在出错时介入 | 客户支持 |
| **人在回路上** | 最高 | 完成后审计日志 | 高流量分析 |

## 中断与断点

现代架构（LangGraph、Microsoft Agent Framework）使用**确定性断点**。

- **模式**：在调用特定敏感工具之前，系统硬编码“暂停”（例如 `execute_purchase` 或 `delete_user`）。
- **决策**：环境等待用户发送 `approve` 或 `reject` 信号。
- **状态保留**：在人采取行动之前，Agent 的推理状态在数据库中保持“冻结”。

## 时间旅行调试（状态编辑）

标准 Agent 是“单向”的。如果它在第 3 步犯错，会话通常就毁了。
- **创新**：**状态注入**。人工审核者可以“回到”第 3 步的状态，编辑 Agent 的观察或思考，然后“恢复”执行。
- **影响**：允许人把 Agent 从错误路径上“引导”出来，而不用从零开始。

## 协同推理（共享草稿本）

人不再只是“裁判”，而成为**“伙伴”**。
- Agent 向人展示它的**草稿本**（内部思考）。
- 典型表达：“我打算使用工具 A，因为事实 B。你觉得这样对吗？”
- **收益**：在推理错误转化为动作之前捕获它们。

---

## 基于置信度的升级

使用支持 Logprobs 或内置推理步骤的模型，计算**不确定性得分**。

- 如果得分超过阈值，Agent **自动暂停**并向人工操作员发送通知。
- **示例**：处理复杂账单争议时，Agent 意识到用户意图有歧义。它停止并说：“我不太确定该如何处理这次特殊退款。请稍等，我让人工专家来查看。”

## 面试问题

### Q：如何设计一个不会让人工操作员“疲劳”的 HITL 系统？

**强回答：**

我们使用**阈值调优**，不会要求审批每个动作。只有以下情况触发 HITL：1）高风险的“写入”工具；2）低置信度推理步骤；3）违反业务“政策”的动作。此外，我们提供**上下文摘要**：不展示完整日志，而是展示 Agent 想做什么的一句话“Diff”。这会把“审查认知负担”从几分钟降到几秒。

### Q：HITL 中的“过度依赖”风险是什么？如何缓解？

**强回答：**

过度依赖发生在人开始不看日志、直接点击“批准”时。我们用**强制审查检查点**缓解（例如人必须至少编辑提议计划中的一个词），或使用**合成错误注入**（有意在 1% 的时间展示“错误”计划，观察人是否能发现）。通过“陷阱”后继续；失败则标记为需要额外培训。
