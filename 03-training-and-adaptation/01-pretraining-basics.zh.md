# 预训练基础

预训练是构建大语言模型时计算成本最高的阶段。模型在海量数据上学习通用知识和语言模式，之后的微调、对齐和推理都建立在这一阶段形成的表示能力之上。

## 预训练目标

现代 LLM 大多采用 **仅解码器（Decoder-only）** 架构，并使用**因果语言建模（Causal Language Modeling，CLM）**：

```python
# 目标：最小化交叉熵损失
Loss = -sum(log P(token_i | token_1, ..., token_{i-1}))
```

模型根据已经看到的上下文预测下一个 token。这个目标本身很简单，但当数据量、模型规模和训练计算量足够大时，会产生涌现的推理能力。

## 数据课程与数据质量

训练重点已经从“数据越多越好”转向“数据课程更好、质量更高”。

### 100T token 的规模

前沿模型（如 Llama 4、GPT-5.5、Claude Opus 4.7、Gemini 3.1 Pro）可能使用 15T 到 100T 个 token 训练。在这个规模下，**去重（Deduplication）**和**质量过滤（Quality Filtering）**是拉开差距的主要因素。

### 数据混合标准

| 组成 | 比例 | 作用 |
|---|---:|---|
| Web（CommonCrawl） | 50%–60% | 通用知识和多样化表达 |
| 代码（GitHub、Stack Overflow） | 15%–20% | 对逻辑与推理能力很关键 |
| 书籍（Project Gutenberg） | 10% | 叙事连贯性和长上下文 |
| 学术资料（arXiv、PubMed） | 10% | 专业技术知识 |
| 合成数据（模型生成） | 5%–10% | 数学、逻辑和特定指令路径 |

**代码带来的影响：**研究表明，提高预训练数据中代码的比例，不仅会提升编程能力，也会提升数学和逻辑谜题等非编程推理任务的表现，因为代码训练了模型的结构化思考方式。

## 缩放定律：训练最优与推理最优

### Chinchilla 范式（2022–2024）

`数据 token 数（D）≈ 20 × 参数量（N）`

按照这个经验，一个 70B 模型大约需要 1.4T 个 token。

### 推理最优范式

现代模型相对于 Chinchilla 建议往往进行了大量过训练。

- **原因：**训练成本通常只支付一次，而推理成本会在数十亿次服务请求中持续产生。
- **结果：**现在可以让 8B 小模型使用 15T 以上 token 训练，使它达到过去 70B 模型的能力，同时显著降低服务成本。

| 策略 | token/参数比例 | 适用场景 |
|---|---:|---|
| Chinchilla | 20:1 | 研究或概念验证 |
| **推理最优** | **200:1–500:1** | 生产部署 |

## 训练稳定性

在超大规模训练中，训练稳定性会成为主要问题。

### 1. Loss Spike

Loss Spike 指损失突然跳升，严重时会毁掉整个训练任务。

- **标准修复：**定期保存 checkpoint，并在异常时自动回滚。
- **架构修复：**使用残差缩放，让残差分支的初始输出接近于零，使训练早期更稳定。

### 2. 精度：FP8 与 BF16

- **BF16：**2023–2024 年的稳定性标准。
- **FP8：**当前的生产标准。H100、B200 等硬件原生支持 FP8；它可以将显存占用减半、吞吐提高约一倍，并通过随机舍入保持训练稳定性。

## 面试问题

### Q：既然 Chinchilla 认为 8B 模型使用约 160B token 更优，为什么还要用 15T token 训练 8B 模型？

**强回答：**Chinchilla 最优讨论的是固定训练计算预算下如何分配模型参数和训练数据。但生产系统更关心总拥有成本（TCO），而 TCO 往往由推理成本主导。对小模型进行过训练，可以把更多能力固化到更少的参数中，从而获得更高 TPS、更低显存占用，同时保持接近前沿模型的质量。

### Q：LLM 预训练中的“课程（curriculum）”是什么？

**强回答：**课程指数据的顺序和混合比例。常见模式是：1）通用知识阶段，占 80%，使用网页和书籍；2）推理强化阶段，占 15%，使用代码、数学和逻辑；3）高质量冷却阶段，最后 1%–5% 使用人工筛选或教材级数据，让模型减少输出抖动并更好地遵循指令。
