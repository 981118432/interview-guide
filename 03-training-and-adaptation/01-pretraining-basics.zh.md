## 预训练目标

现代 LLM 大多是**仅解码器（Decoder-only）**模型，并使用**因果语言建模（Causal Language Modeling，CLM）**：

```python
# 目标：最小化交叉熵损失
Loss = -sum(log P(token_i | token_1, ..., token_{i-1}))
```

模型根据上下文预测下一个 token。这个简单的目标在大规模训练下会带来涌现的推理能力。

## 数据课程与质量

重点已经从“更多数据”转向“更好的数据课程”。

### 100T Token 的规模

前沿模型（Llama 4、GPT-5.5、Claude Opus 4.7、Gemini 3.1 Pro）使用 15T 到 100T 个 token 训练。在这个规模下，**去重（Deduplication）**和**质量过滤（Quality Filtering）**是主要差异来源。

### 数据混合标准

| 组成 | 比例 | 目的 |
|-----------|------------|---------|
| Web（CommonCrawl） | 50–60% | 通用知识、多样化风格 |
| 代码（GitHub、StackOverflow） | 15–20% | **对逻辑与推理至关重要** |
| 书籍（Project Gutenberg） | 10% | 叙事连贯性、长上下文 |
| 学术资料（ArXiv、PubMed） | 10% | 专业技术知识 |
| 合成数据（模型生成） | 5–10% | 数学、逻辑和特定指令路径 |

**细节：“代码效应”：**研究表明，提高预训练混合数据中的代码比例，会提升模型在**非编码**推理任务（例如数学、逻辑谜题）上的表现，因为代码教会了模型结构化思考。

## 缩放定律：训练最优与推理最优

### Chinchilla 范式（2022–2024）

`数据 Token 数（D）≈ 20 * 参数量（N）`

对于一个 70B 模型，这意味着约 1.4T 个 token。

### 推理最优范式

相对于 Chinchilla，现代模型（Llama 3、Llama 4）进行了**大量过训练**。

- **为什么？**训练成本只支付一次；推理成本却要支付数十亿次。
- **结果：**现在会使用 15T+ token 训练小模型（8B），让它们达到旧一代 70B 模型的能力，同时服务成本低得多。

| 策略 | Token/参数比例 | 最适合 |
|----------|-------------------|----------|
| Chinchilla | 20:1 | 研究 / 概念验证 |
| **推理最优** | **200:1 到 500:1** | 生产部署 |

## 训练稳定性

“超大规模”训练（10 万张以上 GPU）面临严重的稳定性问题。

### 1. Loss Spike

损失突然跳升，可能毁掉一次训练任务。

- **标准修复：****定期保存检查点（Periodic Checkpointing）**和**自动回滚（Automatic Rollbacks）**。
- **架构修复：****残差缩放（Residual Scaling）**，初始化权重，使残差分支从接近零开始。

### 2. 精度：FP8 与 BF16

- **BF16：**2023–2024 年的稳定性标准。
- **FP8：**当前的生产标准。H100/B200 原生支持 FP8；它能把显存占用减半、吞吐提高一倍，同时通过**随机舍入（Stochastic Rounding）**保持训练稳定性。

## 面试问题

### Q：既然 Chinchilla 说 160B token 对 8B 模型是最优的，为什么还要用 15T token 训练 8B 模型？

**强回答：**
Chinchilla 最优讨论的是固定**训练**计算预算下的最佳使用方式。但在生产环境中，我们关心的是**总拥有成本（TCO）**，而它主要由推理成本决定。通过过度训练小模型，我们把更多智能“烘焙”进更少的参数中。结果是模型服务效率显著更高（TPS 更高、显存更低），同时保持前沿级质量。

### Q：LLM 预训练中的“课程（curriculum）”是什么？

**强回答：**
课程指数据的顺序和混合。一个常见的现代模式是：
1. **通用知识阶段：**80% 的 token（Web、书籍）。
2. **推理聚焦阶段：**15% 的 token（代码、数学、逻辑）。
3. **高质量“冷却”阶段：**最后 1–5% 的 token 使用极高质量、人工整理或教材级数据。这个“冷却”阶段帮助模型减少抖动，在开始任何微调之前更好地遵循指令。
