# 推理模型训练：RLVR 与 GRPO

前沿推理模型（OpenAI o 系列、DeepSeek-R1、Qwen thinking 模型）的训练方式与 RLHF、DPO 不同：它们大量使用**带可验证奖励的强化学习（RLVR）**。做法是让能力较强的基础模型在数学、代码和逻辑等有可检查答案的问题上生成较长的思维链，并由程序化验证器直接奖励正确性，而不是依赖学习得到的奖励模型。本章介绍 RLVR、DeepSeek 推广的 GRPO、奖励设计的失败模式、强化学习究竟增加了什么能力，以及多数团队更应该优先采用的蒸馏路径。

## RLVR：带可验证奖励的强化学习

RLVR 用确定性的验证器替代 RLHF 的学习型奖励模型。验证器根据事实检查返回奖励：数学答案是否匹配、代码是否通过单元测试、证明是否通过检查。策略是 LLM，环境是一次生成长思维链并给出答案，奖励则由数值/字符串匹配或运行代码得到。

“可验证”很重要，因为它可以绕过大量奖励模型投机。在 RLHF 中，奖励模型本身是神经网络，策略可能利用它的盲点；而“是否等于标准答案”或“测试是否全部通过”更接近外部事实，不能以同样方式被软性评分面欺骗。它不能消除所有投机，例如模型仍可能绕过检查器或用不忠实步骤得到答案。

每一步通常是：

1. 采样有已知答案的问题。
2. 当前策略为每道题生成一个或多个长思维链回答。
3. 对每个回答运行验证器，得到标量奖励，通常是 1/0，也可以加少量格式奖励。
4. 计算 advantage 并执行策略梯度更新。
5. 重复训练。长思维链、自我验证和回溯是循环中涌现的行为，不一定需要逐步人工监督。

DeepSeek-R1 报告了不依赖人工标注推理轨迹、仅用纯 RL 激励推理能力的结果。需要注意的是，OpenAI 没有公开 o 系列的具体算法，因此把它描述为“可能采用 RLVR 风格训练”是基于公开信息的合理推断，而不是已证实的算法细节。

## GRPO

GRPO（Group Relative Policy Optimization）最早在 DeepSeekMath 中提出，并被 DeepSeek-R1 用作强化学习引擎。

### 它解决的 PPO 问题

PPO 需要 value/critic 网络来估计 advantage 的基线。对 LLM 而言，critic 往往与策略模型规模相近，会显著增加显存和训练成本；单个终止奖励的长序列也很难学出稳定的 value 估计。

GRPO 删除 critic，改为对同一个 prompt 采样一组回答，用这一组回答的奖励统计量作为基线。

```python
# 一步 GRPO：policy 是 LLM，verify() 是程序化检查器
for q in sample_prompts(batch):
    group = [policy.generate(q) for _ in range(G)]
    R = [verify(q, o) for o in group]
    mu, sigma = mean(R), std(R)
    A = [(r - mu) / (sigma + 1e-6) for r in R]
    for o_i, A_i in zip(group, A):
        ratio = exp(policy.logprob(o_i) - old_policy.logprob(o_i))
        loss += -mean(min(ratio * A_i,
                          clip(ratio, 1-eps, 1+eps) * A_i))
        loss += beta * KL(policy, ref_policy)
update(policy, loss)
```

对一个 prompt 生成 `o_1...o_G`，得到奖励 `r_1...r_G`；第 i 个回答的 advantage 是它在组内的 z-score，并广播到该回答的每个 token。这样不需要 critic，适合只有一个终止奖励的可验证任务。

### 已知问题与改进

- **长度偏差：**一个标量 advantage 广播到所有 token，可能鼓励模型把回答变长，甚至对错误答案也变长。Dr.GRPO 去掉了造成这种问题的长度和标准差归一化项。
- **零方差坍缩：**如果一组回答全部正确或全部错误，标准差为零，所有 advantage 都接近零，这组数据不产生梯度。DAPO 使用动态采样，过滤掉全对和全错的组，只保留能产生梯度的组，并调整 clip 范围、使用 token 级损失和移除 KL 项。
- **MoE 不稳定：**MoE 模型的路由变化会让 token 级概率比率噪声很大。GSPO 改用整条序列的似然比，提升 MoE 强化学习的稳定性。

实践上应把问题难度控制在模型能力边界附近，并优先考虑 Dr.GRPO、DAPO 或 GSPO 等去偏变体，而不是直接使用原始 GRPO。

## 奖励设计与失败模式

即使奖励可验证，策略优化的也是验证器实际检查的内容，而不是设计者心里的目标。

- **欺骗验证器：**模型可能通过枚举实例标签等方式通过检查，却没有学会目标规律。
- **“奇迹步骤”：**思维链可能通过不忠实的中间步骤得到正确最终答案；只检查结果会同时奖励错误推理。
- **格式奖励压过正确性：**R1-Zero 风格训练可能同时奖励标签格式和答案正确性；如果格式奖励太大，模型会优化更容易投机的信号。
- **长度利用：**模型可能把变长当作通过检查的捷径。可以使用 token 级损失、超长惩罚和长度归一化目标。

还有一个重要警告：某些模型家族中，随机甚至错误的奖励也可能带来明显提升，因为 RL 放大了预训练中已经潜藏的行为。这种结果未必能迁移到其他模型家族，所以评测必须包含不同基础模型家族的基线。

## RL 增加能力，还是提高采样成功率？

这是一个仍有争议的问题：

- 一种观点认为 RL 主要提高 pass@1，并没有增加新能力；基础模型在足够大的 pass@k 下可能达到同样结果。
- 另一种观点认为，足够长的 RL 能解决基础模型在所有 k 下都无法解决的问题，说明它能扩展能力边界。
- 综合观点认为两者都存在：早期 RL 主要让已有正确路径更容易被采样，持续 RL 才可能探索并扩展边界。

更实用的结论是：当预训练留下能力空间，并且 RL 数据正好位于模型能力边界时，RL 的收益最大。已经会做的题和完全不会做的题都不是好的训练数据。Mid-training 也很重要：在通用预训练和 RL 之间加入推理密集型数据，常常能提高基础能力，让后续 RL 更有效。

## 蒸馏：更便宜的路径

对大多数团队来说，RL 不应该是第一步。

### 离线蒸馏

用强推理模型生成轨迹，再对 Student 做 SFT。DeepSeek-R1 报告了用约 80 万条推理轨迹微调 Qwen 和 Llama，蒸馏后的 32B 模型超过了直接在相同 32B 基础模型上做大规模 RL 的结果，而且成本更低。

### 在线蒸馏

Student 生成自己的回答，再让 Teacher 提供逐 token 的密集监督，而不是只给稀疏标量奖励。它同时保留 on-policy 数据的相关性和 SFT 的稳定信号。具体倍数仍应看作单一厂商的报告，而非已经普遍证实的定律。

| 方法 | 轨迹来源 | 奖励/监督 | 成本与稳定性 |
|---|---|---|---|
| SFT/离线蒸馏 | Teacher | 密集 token 目标 | 便宜稳定，但有 exposure bias |
| RL/RLVR | Student 自己生成 | 稀疏标量奖励 | 成本高、稳定性较差、on-policy |
| 在线蒸馏 | Student 自己生成 | Teacher 的密集 token 分布 | 兼顾 on-policy 相关性与密集信号 |

## 实践建议

大约 95% 的团队应该直接使用强推理模型或从强模型蒸馏。只有在同时满足以下条件时才考虑自己做 RLVR：有干净的程序化验证器；基础模型无法通过提示词达到目标行为；有 RL 基础设施、GPU 预算和承受不稳定性的能力；任务位于模型能力边界。

量级上，蒸馏通常需要 10^5–10^6 条高质量 Teacher 轨迹；RLVR 需要数千到数万条按难度筛选的可验证 prompt，而 rollout 往往是主要成本。评测时同时报告 pass@1 和 pass@k，使用多个基础模型家族，检查推理忠实性和回答长度漂移，并避免基准污染。

## 面试问题

### Q：什么是 RLVR？为什么它在推理任务上比 RLHF 更稳定？

**强回答：**RLVR 是带可验证奖励的强化学习。它不用学习型奖励模型，而是用确定性验证器检查数学答案或代码测试结果。奖励来自外部事实，因此不像 RLHF 奖励模型那样容易被策略过度优化。代价是它只适用于可以机械检查正确性的任务，仍然可能出现不忠实推理或验证器投机。

### Q：解释 GRPO，并说明一个失败模式。

**强回答：**GRPO 删除 PPO 的 value/critic 网络，对同一个 prompt 采样多个回答，用验证器评分，再把组内 z-score 作为每个回答的 advantage。零方差坍缩是典型问题：一组回答全对或全错时，标准差和 advantage 都为零，整组不产生梯度。DAPO 通过动态采样过滤掉这类组；另外，广播 advantage 还可能产生长度偏差，Dr.GRPO 会对此进行修正。
