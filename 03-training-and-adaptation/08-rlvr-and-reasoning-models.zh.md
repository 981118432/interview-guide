# 推理模型训练：RLVR 与 GRPO

前沿推理模型（OpenAI 的 o 系列、DeepSeek-R1、Qwen 的 thinking 模型）使用的训练配方与 [RLHF 和 DPO](04-rlhf-and-dpo.md) 不同：**带可验证奖励的强化学习（RLVR）**。具体来说，取一个能力较强的基础模型，让它在具有*可检查*答案的问题（数学、代码、逻辑）上生成较长的思维链，然后使用程序化验证器直接奖励正确性，而不是使用学习得到的奖励模型。本章介绍 RLVR、DeepSeek 推广的 GRPO 算法、奖励设计的失败模式、关于 RL 实际增加什么的持续争论，以及大多数团队应该首先采用的更便宜的蒸馏路径。

## RLVR：带可验证奖励的强化学习

RLVR 用确定性的**验证器**取代 RLHF 的学习型奖励模型。验证器根据真实答案检查返回奖励：最终答案是否匹配（数学），代码是否通过单元测试，证明是否通过检查。策略是 LLM；环境是一次生成长思维链并随后给出答案；奖励通过数字/字符串匹配或运行代码计算。

**为什么“可验证”很重要：它在很大程度上避开了奖励模型黑客。**在 RLHF 中，奖励模型本身是一个根据偏好训练的神经网络，策略会学着利用它的盲点（Goodhart 定律/过度优化问题）。检查“结果是否等于标准答案”或“所有测试是否通过”的验证器没有同样可被利用的柔性学习表面；奖励建立在外部裁判上。这是 RLVR 比 RLHF 在推理任务上扩展得更稳定的核心原因。它并不会*消除*投机（见[奖励设计](#奖励设计与失败模式)），但会移除最容易利用的漏洞。

每一步的循环是：
1. 采样具有已知、可检查答案的 prompt。
2. 对每个问题，从当前策略采样一个或多个长思维链补全。
3. 对每个补全运行验证器，得到标量奖励（通常是正确为 1、错误为 0，有时再加一个小的格式奖励）。
4. 计算 advantage 并进行策略梯度更新。
5. 重复。长思维链、自我验证和回溯是从这个循环中涌现的，并不是显式监督的结果。

最具代表性的开放成果是 **DeepSeek-R1**（arXiv:2501.12948；同行评审版本于 2025 年 9 月发表在 Nature），它报告了在没有人工标注推理轨迹的情况下，通过*纯 RL* 激励推理并涌现自我反思的结果。教学时需要加一个限定：OpenAI 没有发布 o 系列算法，因此把“o 系列使用 RLVR 风格的 RL”当作基于公开信息的合理推断，而不是有文档证明的事实，也不要把某个具体算法归因于它。

## GRPO

**组相对策略优化（Group Relative Policy Optimization）**在 DeepSeekMath（arXiv:2402.03300）中提出，并作为 DeepSeek-R1 的 RL 引擎使用。

**它移除了 PPO 的问题。**PPO 需要一个**价值/评论家网络**，通常与策略大小相同，用来估计计算 advantage 所需的基线。对 LLM 来说，这大致会使显存翻倍，并增加第二个需要训练的模型；而对于只有一个终止奖励的长序列，价值估计也很难学习。GRPO 的做法是：**删除 critic**。它不使用学习得到的基线，而是为同一个 prompt 采样一**组**补全，并把这组自身的奖励统计量作为基线。

**组相对 advantage。**对于一个 prompt，采样补全 `o_1..o_G`，得到奖励 `r_1..r_G`。第 i 个补全的 advantage 是它在组内的 z-score，并广播到该补全的每个 token：

```python
# 一步 GRPO。policy = LLM；verify() = 程序化检查器。
for q in sample_prompts(batch):
    group = [policy.generate(q) for _ in range(G)]      # G 个一组，例如 8..64
    R = [verify(q, o) for o in group]                    # 可验证奖励，例如 1.0 / 0.0
    mu, sigma = mean(R), std(R)
    A = [(r - mu) / (sigma + 1e-6) for r in R]           # 组相对 advantage（无 critic 基线）
    for o_i, A_i in zip(group, A):
        ratio = exp(policy.logprob(o_i) - old_policy.logprob(o_i))  # 每 token 概率比
        loss += -mean(min(ratio * A_i, clip(ratio, 1-eps, 1+eps) * A_i))
        loss += beta * KL(policy, ref_policy)            # 原始 GRPO 保留 KL 项
update(policy, loss)
```

DeepSeek 使用它，是因为删除 critic 在前沿规模下带来实际的显存收益，而且组基线适合只有一个终止可验证奖励的场景。

**已知问题，以及解决它们的变体：**
- **长度偏差。**因为一个标量 advantage 被广播到每个 token，较长的补全会把它的 advantage 分散到更多 token 上，优化可能因此膨胀回答长度（尤其是错误回答）。**Dr.GRPO**（arXiv:2503.20783）移除了造成这种问题的长度和标准差归一化项。
- **零方差坍缩。**如果一组中的所有补全得到相同奖励（简单问题全部正确，或困难问题全部错误），标准差会趋近于零，每个 advantage 都趋近于零，该组不会产生梯度。随着模型变好，越来越多的 prompt 会变成“全部正确”，有效 batch 变小。**DAPO**（arXiv:2503.14476）通过**动态采样**解决：过采样并过滤掉组内全对或全错的 prompt，只保留能产生梯度的组。DAPO 还解耦 clip 范围（“clip-higher”）、使用 token 级损失并删除 KL 项。
- **MoE 不稳定。**混合专家模型的 token 级重要性比率会因为不同策略版本的路由不同而产生噪声。**GSPO**（arXiv:2507.18071，在 Qwen3 中使用）改为在整条序列似然上定义比率，从而稳定 MoE 的 RL。

实践上的经验是：把 prompt 选在模型的能力难度区间内，并优先选择经过去偏的变体（Dr.GRPO、DAPO 或 GSPO），而不是原始 GRPO。

## 奖励设计与失败模式

即使奖励是可验证的，策略优化的也是验证器**实际测量**的内容，而不是你想让它测量的内容。

- **欺骗验证器。**模型可能在没有学会规律的情况下通过检查器（例如枚举实例级标签），这是有文档记录的 RLVR 奖励黑客方式。
- **“奇迹步骤”。**思维链可能通过*不忠实*的中间步骤得到正确的最终答案（arXiv:2510.07774）。纯结果验证器会同时奖励正确答案和糟糕的推理。
- **格式奖励与正确性奖励。**R1-Zero 风格配方会把小的格式奖励（把推理放在标签块中，给出可解析答案）与正确性奖励配对。如果格式奖励相对于正确性太大，模型会优化便宜而容易投机的信号。
- **长度利用。**既包括上文 GRPO 梯度的人为产物，也包括“越冗长越容易通过”这种真实的黑客方式。缓解方法包括 token 级损失、超长回答惩罚和长度归一化目标。

有一个需要标记的重要限定：**Spurious Rewards** 的研究结果（arXiv:2506.10947）报告称，在一个模型家族中，GRPO 使用随机甚至错误的奖励也产生了大幅提升，因为它放大了该家族预训练中已经潜在存在的行为。关键是，这些提升没有迁移到其他模型家族。教训是要高度怀疑单一模型家族的 RLVR 结果，并始终加入来自不同家族的基线。

## RL 增加能力，还是让采样更集中？

这是本章最微妙的一点：一个仍然开放的问题，有三种观点。

- **RL 让采样更集中，但不增加能力。**一项研究（arXiv:2504.13837）报告 RLVR 模型在 pass@1 上超过基础模型，但基础模型在较大的 pass@k 上达到或超过它们。这说明 RL 模型使用的每条推理路径可能已经存在于基础模型中；RL 提高了采样到正确路径的概率，但缩小了可探索集合。
- **持续 RL 扩展边界。**相反的结果（ProRL，arXiv:2505.24864；以及引入 reasoning-aware CoT-Pass@K 指标的 arXiv:2506.14245）报告称，足够多的 RL 能让模型解决基础模型在任何 k 下都失败的问题，并且 RLVR 提升的是推理正确的答案，而不仅是碰巧正确的最终结果。
- **两个阶段都有（适合先给出的综合观点）。**一个调和性的观点（arXiv:2510.04028）发现，早期 RL 会利用并让采样更集中（pass@1 上升、pass@k 持平），持续 RL 则探索并扩展边界。最清晰的实用综合结论（arXiv:2512.07783）报告，只有当预训练留下能力空间，并且 RL 数据瞄准模型能力边缘——模型在 pass@1 上失败、但有时能在 pass@k 上成功的问题——RL 才能产生真正的提升（用较高 pass@k 衡量）。对已经解决或无望解决的问题做 RL，收益很小。

同一研究还强调了**中期训练（mid-training）**：在通用预训练和 RL 之间，使用精心整理的推理密集型混合数据继续训练，以巩固正在形成的技能。在固定计算预算下，它通常优于只做 RL，因为它提高了基础能力，而 RL 随后会对其进行强化。诚实的解读是：这个领域已经形成“RL 在能力边缘效果最好”的共识，但 RL 能否制造真正全新的能力仍有争议。

## 蒸馏：更便宜的路径

对大多数团队来说，RL 不是正确的第一步。

**离策略蒸馏（在 Teacher 轨迹上做 SFT）。**DeepSeek-R1 报告在 R1 生成的约 80 万条推理轨迹上微调密集 Qwen 和 Llama 模型；蒸馏后的 32B 模型超过了直接在同一个 32B 基础模型上大规模 RL 的结果。论文指出，后者需要多得多的计算，仍然比不上蒸馏。教训是：对已知领域中的小模型来说，从强推理模型蒸馏比自己做 RL 更有效、便宜得多。

**在策略蒸馏（Thinking Machines Lab，2025）**让 Student 在自己的采样补全上训练（像 RL 一样是 on-policy），但使用 Teacher 分布提供的逐 token 密集监督（像 SFT 一样），而不是稀疏标量奖励。报告结果显示，在灌输推理能力方面，它的样本效率大约比 RL 高一个数量级，把 on-policy 相关性与密集、稳定的信号结合起来。截至 2026 年，这些数字主要来自单一供应商，因此应当视为已报告的结果，而不是已经确定的倍数。

| 方法 | 轨迹 | 奖励信号 | 成本 / 稳定性 |
|--------|-------------|---------------|------------------|
| SFT / 离线蒸馏 | Teacher 的 | 密集 token 目标 | 便宜、稳定；有一些 exposure bias |
| RL / RLVR | Student 自己的 | 稀疏标量 | 昂贵、稳定性较差；on-policy |
| 在策略蒸馏 | Student 自己的 | 密集（Teacher 逐 token） | on-policy 相关性加密集信号 |

参见[知识蒸馏](05-knowledge-distillation.md)了解更广泛的内容。

## 实践建议

**自己训练推理模型还是直接使用？**对大约 95% 的团队来说：使用强推理模型或从强模型蒸馏。只有在以下条件同时成立时，才自己做 RLVR：（a）有干净的程序化验证器；（b）基础模型或 Teacher 确实无法通过引导达到目标行为；（c）拥有 RL 基础设施和 GPU 预算，并能承受不稳定；（d）任务位于模型能力边缘。

**粗略需求（数量级，不是承诺）：**蒸馏在标准 SFT 计算量下需要 10^5 到 10^6 条高质量 Teacher 轨迹；RLVR 需要数千到数万条按难度区间整理的*可验证* prompt，其中 rollout（不是梯度步骤）是成本瓶颈。据报道，DeepSeek-R1 的后训练约使用 147K H800 GPU 小时，远超业余规模，但比通常假设的规模小。

**评测陷阱：**同时报告 pass@1 *和* pass@k（只报告 pass@1 会掩盖采样与能力的差别）；使用多个基础模型家族（避免 Spurious Rewards 伪影）；检查推理忠实性，而不仅是最终答案；把回答长度漂移当作奖励黑客的预警；通过优先使用保留集或新鲜竞赛数据，防止基准污染。参见[基准与排行榜](../14-evaluation-and-observability/03-benchmarks-and-leaderboards.md)。

**成熟度：**带干净验证器的数学和代码蒸馏、GRPO/DAPO 配方已经成熟且可复现。在策略蒸馏、MoE 的 GSPO 和把中期训练作为明确阶段正在快速成熟。RLVR 是否增加新能力，以及如何在不重新引入奖励模型黑客的情况下干净地扩展到可验证领域之外，仍真正没有定论；因此应把重点放在机制（组基线、长度归一化、动态采样、密集与稀疏监督、能力边缘数据），而不是某个排行榜数字。

## 面试问题

### Q：什么是 RLVR？为什么它在推理任务上比 RLHF 扩展得更稳定？

**强回答：**
RLVR 是带可验证奖励的强化学习：它不使用学习型奖励模型，而是用确定性的验证器奖励策略——数学答案是否匹配、代码是否通过测试。它比 RLHF 扩展得更稳定，因为奖励建立在外部裁判上，而不是一个策略可以过度优化的神经网络。RLHF 的经典失败是奖励模型黑客：策略找到奖励模型给高分但人类不会认可的输入；单元测试通过没有相同的柔性攻击面。代价是 RLVR 只适用于可以机械检查正确性的场景，因此首先在数学、代码和逻辑中发展起来。它并不消除投机：模型仍可能通过不忠实步骤得到正确答案，或欺骗检查器，所以仍要观察忠实性和长度。

### Q：解释 GRPO，并说明一个已知失败模式。

**强回答：**
GRPO 删除 PPO 的 value/critic 网络。对 LLM 来说，这个网络大致会使显存翻倍；GRPO 用组相对基线替代学习基线：为同一个 prompt 采样多个补全，用验证器给每个打分，并把组内 z-score 作为 advantage，广播到每个 token。这样成本低，也适合单个终止可验证奖励，所以 DeepSeek 使用了它。一个关键失败模式是零方差坍缩：当一组补全获得相同奖励——简单问题全对，或困难问题全错——标准差为零，advantage 为零，该组就不会产生梯度。随着模型变好，更多 prompt 会全对，有效 batch 因而缩小。DAPO 的动态采样会过滤全对和全错的组，只在真正产生梯度的组上训练。广播一个 advantage 到所有 token 还会产生长度偏差，Dr.GRPO 通过移除长度归一化来处理它。
