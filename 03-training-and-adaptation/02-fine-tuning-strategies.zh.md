# 微调策略

微调把预训练模型适配到特定任务、领域或风格。如今，微调已经不太是“教会事实”，而更多是“教会格式和行为”。

## 什么时候进行微调

在微调之前，先问：**这个问题能否通过提示词工程或 RAG 解决？**

| 需求 | 更好的方案 | 原因 |
|-------------|-----------------|-----|
| 新事实 / 新知识 | **RAG** | LLM 不擅长通过微调记忆事实；RAG 更容易更新。 |
| 特定输出格式 | **微调** | 教会模型可靠输出 JSON/XML，而不需要复杂提示词。 |
| 语气 / 人格 | **微调** | 比 system prompt 一致得多。 |
| 降低延迟 | **微调** | 减少对长 few-shot 提示的需要。 |
| 私有领域语言 | **继续预训练** | 教会模型专业词汇（医疗、法律、自定义代码）。 |

## 监督微调（SFT）

这是预训练之后的第一步。模型在 `(Prompt, Response)` 对上训练。

### 质量层级

**1000 条“完美”样本胜过 1,000,000 条有噪声样本。**

- **黄金数据集：**由领域专家人工整理（技术任务需要博士水平专家）。
- **负向约束训练：**加入模型**不应该**做什么的例子（例如“不要道歉”“不要提到你是 AI”）。

---

## 继续预训练（领域适配）

也称为“第二阶段预训练”。

- **如何做：**在特定领域的原始文本上训练（例如为金融模型使用所有 SEC 文件）。
- **目标：**学习该领域语言的统计分布。
- **细节：**需要低得多的学习率（约为原始学习率的 1/10），以防止“灾难性遗忘”。

## PEFT 与全参数微调

| 特征 | 全参数微调 | PEFT（LoRA、QLoRA） |
|---------|-------------------|--------------------|
| GPU 显存 | 很高（模型大小 * 4–12） | 较低（模型大小 * 1.5） |
| 速度 | 基准 | 快 2–3 倍 |
| 风险 | 高（灾难性遗忘） | 低 |
| 部署 | 每个任务一个模型 | 一个基础模型 + 多个适配器 |
| **结论** | 保留给基础模型训练 | **生产标准** |

## 超参数调优

### 1. 学习率（LR）

- **SFT：**`1e-5` 到 `5e-5` 是标准范围。
- **过高：**模型会“坍缩”，开始重复或说乱码。

### 2. LoRA 的秩（r）

- 复杂推理任务使用更高的秩（`r=64` 到 `r=256`）。
- 简单风格/语气变化使用更低的秩（`r=8`）。

### 3. 打包训练（Packing）

为了最大化吞吐，我们把多个短样本“打包”到单个 4k 或 8k 序列中，并用 EOS token 分隔。

- **挑战：**自注意力可能在样本之间泄漏。
- **解决方案：****带块掩码的 FlashAttention**，阻止跨样本注意力。

## 面试问题

### Q：为什么使用继续预训练，而不是把领域数据直接放进 SFT 集合？

**强回答：**
SFT 在数据制作方面成本很高——你需要 prompt/answer 对。继续预训练允许你利用海量原始、无标注的领域文本，让模型的内部表示学习专业词汇和风格。模型“会说这种语言”之后，再使用少量 SFT 数据教它用这种语言完成任务（例如分类、摘要）。

### Q：如何防止模型在微调过程中“忘掉”通用能力？

**强回答：**
这叫“灾难性遗忘”。有两个主要缓解方法：
1. **回放（Rehearsal）：**在微调集合中混入 5–10% 的原始预训练数据。
2. **PEFT（LoRA）：**因为我们只训练一小部分权重，原始“知识”仍冻结在基础模型权重中，显著降低遗忘风险。
