# 微调策略

微调是把预训练模型适配到特定任务、领域或风格的过程。现在微调的重点已经不只是“教模型事实”，更多是“教模型输出格式和行为”。

## 什么时候应该微调

在开始微调前，先问：这个问题能不能通过提示词工程或 RAG 解决？

| 需求 | 更合适的方案 | 原因 |
|---|---|---|
| 新事实、新知识 | **RAG** | 微调不适合记忆频繁变化的事实，RAG 更容易更新 |
| 特定输出格式 | **微调** | 可以稳定输出 JSON/XML，减少复杂提示词 |
| 语气或人格 | **微调** | 比只依赖 system prompt 更一致 |
| 降低延迟 | **微调** | 可以减少很长的 few-shot 提示 |
| 私有领域语言 | **继续预训练** | 学习医疗、法律或自定义代码等专业词汇 |

## 监督微调（SFT）

SFT 是预训练之后的第一步。模型在 `(Prompt, Response)` 输入输出对上继续训练。

### 数据质量层级

**1000 条完美样本胜过 100 万条噪声样本。**

- **黄金数据集：**由领域专家人工筛选，技术任务最好由具备研究或博士水平的专家审核。
- **负向约束训练：**加入模型“不应该做什么”的示例，例如“不必道歉”或“不要提及自己是 AI”。

## 继续预训练（领域适配）

继续预训练也叫“第二阶段预训练”。

- **做法：**在某个领域的原始文本上训练，例如把全部 SEC 文件用于金融模型。
- **目标：**学习该领域语言的统计分布。
- **注意：**通常需要使用原始学习率约十分之一的更低学习率，避免灾难性遗忘。

## PEFT 与全参数微调

| 特征 | 全参数微调 | PEFT（LoRA、QLoRA） |
|---|---|---|
| GPU 显存 | 很高，约为模型规模的 4–12 倍 | 较低，约为模型规模的 1.5 倍 |
| 速度 | 基准 | 快约 2–3 倍 |
| 风险 | 高，容易灾难性遗忘 | 低 |
| 部署 | 每个任务一份模型 | 一个基础模型加多个适配器 |
| **结论** | 主要用于基础模型训练 | **生产环境标准方案** |

## 超参数调优

### 1. 学习率

- **SFT：**`1e-5` 到 `5e-5` 是常见范围。
- **过高的风险：**模型会“坍缩”，开始重复输出或产生乱码。

### 2. LoRA 的秩 `r`

- 复杂推理任务使用更高的秩，例如 `r=64` 到 `r=256`。
- 只改变风格或语气时可以使用较低的秩，例如 `r=8`。

### 3. 打包训练（Packing）

为了提高吞吐，可以把多个短样本打包到一个 4k 或 8k 序列中，并用 EOS token 分隔。

- **挑战：**自注意力可能跨样本泄漏信息。
- **解决方案：**使用带 block mask 的 FlashAttention，阻止不同样本之间互相注意。

## 面试问题

### Q：为什么使用继续预训练，而不是把领域数据直接放进 SFT 数据集？

**强回答：**SFT 对数据制作要求很高，需要成对的 prompt 和 answer。继续预训练可以利用大量没有标注的领域原始文本，让模型的内部表示先学习专业词汇和表达风格。模型“会说这个领域的语言”之后，再使用少量 SFT 数据教它完成分类、摘要等具体任务。

### Q：如何避免模型在微调时遗忘通用能力？

**强回答：**这叫灾难性遗忘，主要有两种缓解方式：1）回放训练，在微调数据中混入 5%–10% 原始预训练数据；2）使用 PEFT/LoRA，只训练少量参数，把原有知识冻结在基础模型中，从而显著降低遗忘风险。
