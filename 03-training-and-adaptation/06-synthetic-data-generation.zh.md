# 合成数据生成

## “数据墙”之后：合成转向

前沿模型（Llama 4、GPT-5.5、Claude Opus 4.7、Gemini 3.1 Pro）使用 100T+ token 训练。没有足够的人类文本来维持这种扩展。
**现实情况：**如今，前沿模型微调训练混合数据中超过 **50%**（预训练中为 10%）是合成数据。

| 来源 | 人类数据 | 合成数据 |
|--------|------------|----------------|
| **数量** | 固定（有限） | 无限 |
| **质量** | 可变（有噪声） | 可控（净化） |
| **成本** | 高（人工标注者） | 低（推理/GPU） |
| **偏见** | 互联网的镜像 | 可以人工平衡 |

## Evol-Instruct 模式

Evol-Instruct 是一个递归过程：LLM 接收一个简单指令，并把它演化成更复杂的指令。

**演化方向：**
1. **广度：**增加任务数量。
2. **深度：**加入约束、复杂因素或多步逻辑。
3. **去噪：**清理措辞，去除“AI 腔”。

```python
# 简单指令：“写一个把两个数字相加的函数。”
# 演化指令：“写一个线程安全的 Python 类，实现矩阵加法，包含
# 错误处理和单元测试，遵循 PEP8。”
```

## Constitutional AI 与 AI 反馈（RLAIF）

Constitutional AI 由 Anthropic 开发，并被行业广泛采用。RLAIF 使用一部“宪法”（一组规则）指导模型评估和改进自己的数据。

**循环：**
1. **提出：**模型 A 生成回答。
2. **批评：**模型 B（宪法评审者）根据准则识别缺陷。
3. **修订：**模型 A 根据批评生成更好的版本。
4. **训练：**最终的（Prompt，修订后回答）对加入 SFT 集合。

## 可验证的合成数据

合成数据最大的风险是**模型坍缩**（模型学会自己的错误）。
**2025 年的解决方案：**聚焦于不需要 LLM 就能验证“真相”的领域。

- **数学：**使用形式化验证（Lean/Isabelle）或 Python 执行验证答案。
- **代码：**用测试用例（单元测试）运行生成的代码。
- **RAG：**使用“黄金上下文”生成答案明确存在于文本中的问题。

## 去偏与多样性

合成数据被用来“填补”人类数据中的空白。
- **语言：**通过翻译概念模板，生成低资源语言（例如斯瓦希里语、马拉地语）的高质量文本。
- **逻辑：**生成某种特定逻辑谬误的 1,000,000 个变体，让模型对它进行“加固”。

## 面试问题

### Q：使用合成数据训练时，“模型坍缩”的风险是什么？

**强回答：**
模型坍缩发生在模型使用早期版本自身生成的数据进行训练时。因为模型的分布比真实世界更窄（它对某些词和模式有偏好），训练循环变成错误和乏味的“正反馈循环”。到 2025 年，我们通过以下方式缓解：
1. 混入 5–20% 的“黄金”人工认证数据。
2. 使用“可验证”奖励（数学/代码），确保错误不会被学习。
3. 使用更强大的“Teacher”模型为“Student”模型生成数据。

### Q：如何保证 1000 万行合成数据集的质量？

**强回答：**
我们使用**多阶段过滤流水线**：
1. **语义去重：**使用 embedding 移除近似相同的聚类。
2. **LLM-as-Judge：**抽样 1% 数据，让更强模型（例如 GPT-5.2）从逻辑和安全角度评分。
3. **困惑度过滤：**使用小模型计算文本困惑度。太高（无意义）或太低（重复/简单）的数据被丢弃。
4. **可验证执行：**如果数据包含代码或数学内容，必须通过本地编译器/解释器检查。
