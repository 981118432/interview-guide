# 合成数据生成

当高质量人工数据越来越难获取时，合成数据成为训练和评测的重要来源。它可以扩展长尾场景、制造困难样本、生成程序化标签，也可以用于偏好模型和推理模型训练。

## 数据墙之后的合成转向

公开网页数据并不是无限的，高质量数据还需要去重、过滤和授权。大模型可以根据任务规范生成新样本，但合成数据并不天然可靠：生成模型的错误、偏见和模式会被批量复制，因此质量控制必须和生成过程同时设计。

## Evol-Instruct 模式

Evol-Instruct 通过逐步增加约束，把简单指令演化成复杂任务。

```text
简单指令：写一个把两个数字相加的函数。
演化指令：写一个线程安全的 Python 矩阵加法类，加入错误处理和单元测试，并遵循 PEP8。
```

演化操作可以增加上下文、约束、推理步骤、边界条件或输出格式，也可以让另一个模型检查难度是否真的提高。

## Constitutional AI 与 RLAIF

Constitutional AI 使用一组明确原则指导模型批评和改写自己的回答；RLAIF 使用 AI 反馈代替部分人工偏好标注。它们可以降低人工标注成本，但原则本身、反馈模型和拒答边界仍然需要人工审核。

## 可验证合成数据

数学、代码和结构化任务应尽量使用可执行验证器：运行单元测试、编译代码、检查 JSON Schema、验证数学答案或执行规则检查。通过验证后再把样本加入训练集，比单纯让另一个 LLM 打分更可靠。

## 去偏与多样性

合成数据容易重复 Teacher 的语气和偏见，也容易让训练集变得过于均匀。需要使用多种生成提示、多个模型和多种采样温度，并对主题、长度、难度、语言和答案形式分层去重。

## 质量控制流程

推荐流程是：生成候选样本 → 规则过滤 → 可执行验证 → 多模型交叉检查 → 去重 → 难度分层 → 人工抽样 → 污染检测 → 独立评测。对于 1000 万条数据，不能只看总量，必须保留来源、生成模型、验证结果和过滤原因等元数据。

## 面试问题

### Q：使用合成数据训练时，模型坍缩有什么风险？

**强回答：**如果模型反复在模型生成的数据上训练，数据分布会越来越窄，少数错误和表达模式会被放大，导致多样性和泛化能力下降。缓解方式包括混入真实数据、控制合成数据比例、使用多代教师、去重、独立验证，以及在未见任务上持续评测。

### Q：如何保证 1000 万行合成数据的质量？

**强回答：**先定义验收指标和数据契约，再建立分层采样，而不是逐行人工检查。对代码运行测试，对结构化输出做 schema 校验，对事实做检索或多模型交叉核验；同时做去重、污染检测、难度分布分析和人工抽检，并保留可追溯元数据。
