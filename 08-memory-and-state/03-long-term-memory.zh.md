# 长期记忆

长期记忆（L2 和 L3）提供跨会话持久化能力。生产级技术栈已经从简单的“历史 RAG”转向结合向量、图和关系数据的**多表示存储**。Zep、Mem0、Letta、Cognee 等专用记忆服务开箱即用地封装了对话摘要、实体提取和时间感知能力。

## 情景记忆：个人日志

情景记忆存储**轨迹**：事件及其结果组成的序列。
- **数据结构**：`(Timestamp, Interaction_ID, Trajectory_Summary, Embedding)`。
- **理由**：如果 Agent 上个月使用特定工具序列成功构建了一个 React 组件，那么今天再次被要求构建类似组件时，它应该能够“回忆”这次成功。
- **实现提示**：我们保存用于检索的*摘要*，并把*原始日志*存入冷存储（S3/GCS）供取证分析。

---

## 语义记忆：事实存储

语义记忆存储关于实体的**已发现事实**。
- **实体识别**：使用“事实提取 Agent”解析用户的每一轮消息。
- **三元组示例**：
  - `(User_1, HAS_PREFERENCE, Dark_Mode)`
  - `(Company_X, USES_SDK, Stripe)`
- **技术**：知识图谱（Neo4j、AWS Neptune）结合关系型标签。

## 混合向量-图存储

Staff 级工程师会使用 **GraphRAG 风格的记忆**。
- **向量搜索**找到“相关”节点。
- **图遍历**找到“相连”节点。
- **收益**：搜索“Project Alpha”时，向量搜索能找到名称，而图遍历还能找到 10 名开发者、截止日期和关联代码仓库。

## 记忆剪枝与衰减

如果不受控制地增长，记忆就会变成负担。
- **时间衰减**：除非经常访问，否则旧记忆的“相关性分数”会降低。
- **巩固**：把关于“账单”的 10 次独立交互合并成一个高质量摘要节点。
- **显式遗忘**：通过删除与用户 ID 关联的全部情景和语义集群，遵守 GDPR“被遗忘权”。

## 隐私与多租户

> [!CAUTION]
> **跨会话泄漏**是全局记忆中最大的安全风险。
> 确保 `user_id` 是向量数据库元数据中的硬分区键。绝不要依赖 LLM 按用户过滤结果。

## 面试问题

### Q：如何在向量数据库和知识图谱之间选择长期记忆存储？

**强回答：**
我会用**向量数据库**存储**情景上下文**（非结构化日志、过去的对话），因为需要根据含义进行“模糊”匹配；用**知识图谱**存储**结构化的语义知识**（关系、属性、层级），因为需要“确定性”遍历。生产系统会采用**混合**方式：向量索引指向图 ID，让系统先找到合适的“起始节点”，再进行遍历以获取高精度上下文。

### Q：在学习型 Agent 记忆中，“灾难性遗忘”是什么？

**强回答：**
在微调 Agent 中，灾难性遗忘指新的训练数据抹去旧知识。在**Agent 记忆（基于 RAG）**中，它指的是**索引过载**：如果 Agent 向记忆中加入 1,000 条低质量新“事实”，检索精度就会下降，旧的高质量事实被噪声掩埋，表现得像是“忘记”了它们。我们通过**质量加权检索**缓解这一问题：来自监督器、拥有较高“验证分数”的记忆，其权重高于原始日志。
