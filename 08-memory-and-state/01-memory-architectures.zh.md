# 记忆架构

LLM 记忆已经从“历史缓冲区”演进为**三层认知架构**。这一层级模拟人类认知系统（L1～L3），在速度、成本和召回容量之间取得平衡。当前生产级 Agent 技术栈通常在向量存储之上使用专用记忆层（Mem0、Zep、Letta、Cognee），而不是自行重复构建。

## 三层层级

| 层级 | 类型 | 人类类比 | 技术 | 延迟 |
|------|------|---------------|------------|---------|
| **L1** | 工作记忆 | 当前注意焦点 | 上下文窗口 / KV Cache | <50ms |
| **L2** | 情景记忆 | 过去的经历 | 向量数据库 / 本地图 | 100-300ms |
| **L3** | 语义记忆 | 通用知识 | 全局图 / SQL / Mem0 | >500ms |

---

## 第 1 层：工作记忆（L1）

L1 是模型的**当前活跃焦点**。
- **上下文窗口**：当前前沿模型（Claude Opus 4.7、Claude Sonnet 4.6、GPT-5.5、Gemini 3.1 Pro）支持 128K～2M Token。
- **KV Cache**：保存预计算 Key 和 Value 的 GPU“内存”。
- **管理策略**：**滑动窗口**和**前缀缓存**（vLLM/PagedAttention）。
- **冗余提示**：L1 只保留最近几轮以及关键系统指令。

---

## 第 2 层：情景记忆（L2）

L2 保存本次会话或与该用户过去会话中“之前发生了什么”。
- **存储**：向量数据库（Pinecone、Weaviate、Qdrant）。
- **检索**：语义搜索。如果用户问“我们上周二聊了什么？”，L2 就会提供答案。
- **模式**：**经验回放**。Agent 检索过去成功的轨迹，指导当前决策。

---

## 第 3 层：语义记忆（L3）

L3 保存**不可变事实**和**学到的规则**。
- **知识图谱**：保存关系（例如，`User` -- `WORKS_FOR` --> `Company_X`）。
- **Mem0**：一种托管服务，负责提取事实（例如“用户喜欢深色模式”），并让事实在全局可用。
- **真值锚定**：当 L1 和 L2 提供的信息冲突时，L3 充当“事实真相”。

---

## 记忆巩固模式

记忆通过**巩固**在不同层级之间移动：
1. **提取**：会话结束时，LLM“审查器”从 L1 中提取事实。
2. **索引**：事实被存入 L2（作为向量）和 L3（作为图节点）。
3. **衰减**：长期未被强化的旧记忆被移入冷存储（L3）或删除。

## 面试问题

### Q：为什么不直接使用 2M Token 的上下文窗口承载所有记忆（L1～L3）？

**强回答：**
虽然可行，但在**经济和认知层面都不高效**。
1. **成本**：每轮都用 100 万以上 Token 调用模型，成本显著高于通过 RAG 召回上下文后进行 1 万 Token 的调用。
2. **注意力稀释**：即使是“长上下文”模型，“中间丢失”仍然存在。如果上下文堆满不相关的历史轮次，模型对**当前**任务的推理质量会下降。
3. **延迟**：由于需要加载 KV Cache，TTFT（首 Token 时间）会随上下文规模增长。
Staff 级架构会使用**策略性检索**，让上下文窗口保持精简、聚焦。

### Q：如何处理第 3 层（全局语义记忆）中的“隐私泄漏”？

**强回答：**
第 3 层（语义记忆）必须按**命名空间分片**。每个用户或组织在向量数据库和知识图谱中都应拥有唯一的 `namespace_id`。我们在数据库层实现 **RLS（行级安全）**。此外，在巩固步骤中使用**PII 清理层**，确保密码、个人身份信息等敏感数据不会从临时的 L1 上下文进入持久化的 L3 知识存储。
